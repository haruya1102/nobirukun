# コミットルール

## フォーマット

Conventional Commits を使う。**メッセージは日本語で書く。**

```
<type>: <subject>

<body（任意）>
```

### type

- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメントのみ
- `style`: フォーマット・セミコロン等（動作に影響しない）
- `refactor`: リファクタ（機能追加・バグ修正を含まない）
- `test`: テストの追加・修正
- `chore`: ビルド・依存・設定など雑務

### subject（タイトル）

- **日本語**で書く
- 50文字以内を目安にする
- 「〜を追加」「〜を修正」のように簡潔にまとめる（体言止めも可）
- 末尾に句点（。）はつけない
- 例:
  - `feat: ストレッチキャラクターのscaleYアニメーションを追加`
  - `fix: 月次リセット時のタイムゾーンずれを修正`
  - `docs: CLAUDE.mdに成長計算ロジックの概要を追記`

### body（本文・任意）

- 「**なぜ**そうしたか」を書く（「何をしたか」はdiffを見れば分かる）
- 日本語で書き、1行は適度に折り返す
- 複雑な変更・設計判断・トレードオフがある場合のみ書く

## 粒度

- **1コミット1目的**（atomic commit）
- 無関係な変更を同じコミットに混ぜない

## やってはいけないこと

- `.env*` や秘密鍵・APIキーを含むコミット
- `git add .` / `git add -A` の盲目的な使用（意図したファイルだけstageする）
- `--no-verify` で pre-commit hook をスキップする（hookが失敗したら原因を直す）
- push済みコミットへの `--amend` や force push（履歴書き換え不可）

## Claude Codeが作るコミット

- 末尾に `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>` を入れる
- コミット作成前に `git status` / `git diff` で内容を確認する
- ユーザーが明示的に指示した時のみコミットを作成する
